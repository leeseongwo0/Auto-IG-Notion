# Dot 작업 지침

`dot-bootstrap.md`로 구성한 뒤 아래 지침으로 수집을 반복합니다. 현재 실제 계정·DB 연결이나 예약 설정이 완료된 상태는 아닙니다.

## 입력값

- Instagram 계정: `<config/local.json의 instagram 항목 또는 사용자가 제공한 대상>`
- 지표 원본: Meta Business Suite 우선. 필요한 지표만 Instagram 인사이트로 보완.
- Notion 대시보드 페이지: `<config/local.json의 notion.dashboard_page_url 또는 사용자 제공 URL>`
- Notion 기록 대상 DB: `<실제로 확인한 콘텐츠·콘텐츠 지표·계정 지표 DB URL; 페이지 URL과 구분>`
- Notion 속성: `notion/schema.json`에 정의한 정확한 이름·유형.
- 행의 의미: 콘텐츠 DB는 게시물당 한 행, 콘텐츠·계정 지표 DB는 날짜·집계 범위별 관측 한 행.
- 관측 기준일 시간대: `Asia/Seoul`
- 콘텐츠 대상: 정기는 최근 30일 내 게시한 게시물·릴스. 최초 수집은 `docs/initial-import.md`에 따라 접근 가능한 이전 콘텐츠까지 포함.
- 계정 조회·도달 집계 범위: `<원본에서 확인한 기간과 시간대>`
- 실행 방식: `<최초 점검 / 기존 지표 최초 수집 / 정기 수집 / 실패 항목 재처리>`

## 작업

당신은 지정된 Instagram 프로페셔널 계정의 지표를 확인해 지정된 Notion 데이터베이스에 기록한다. 이 저장소의 `docs/workflow.md`를 데이터 처리 규칙으로 따른다. 문서를 읽을 수 없다면 작업을 시작하기 전에 해당 내용을 입력으로 제공받는다. 로컬 설정은 Git에 포함되지 않으므로 새 환경에서 없을 수 있다. `YOUR_ACCOUNT` 같은 예제값을 실제 대상으로 사용하지 않는다. 인증값은 연결 설정에서 처리하고 설정 파일·보고서에 기록하지 않는다.

1. 실제 사용할 수 있는 연결 도구 또는 로그인된 브라우저를 확인한다. Instagram 계정과 Notion 대상 DB가 입력과 일치하는지 확인한다. 입력이 비어 있으면 쓰기를 시작하지 말고 필요한 값만 요청한다.
2. 생성된 세 DB의 속성과 관계를 명세에 대조한다. DB 주소가 비어 있으면 최초 구성 지침을 먼저 수행한다. 사용자가 입력한 메모 등 수집 범위 밖의 속성을 보존한다.
3. 계정 팔로워 수와 원본에 표시되는 조회·도달 및 집계 기간을 수집한다. 과거 기간 통계에는 현재 팔로워 수를 복제하지 않는다. 초기 수집과 재개는 별도 최초 수집 지침을 따른다.
4. 대상 게시일 범위의 게시물·릴스를 탐색한다. 콘텐츠별 ID 또는 고유 링크, 종류, 게시 시각, 조회·도달·좋아요·댓글·저장·공유를 수집한다. 목록 탐색이 끝났는지 확인한다.
5. 모든 값에 실제 수집 시각과 관측 기준일을 연결한다. 순간값·누적값·기간 지표를 구분하고, 원본 지표명과 기간을 보존한다. 누락을 0으로 만들거나 축약값을 정확값으로 간주하지 않는다.
6. 같은 대상의 실행을 직렬화한다. 계정과 콘텐츠 ID 또는 고유 링크로 콘텐츠 기본 행을 조회·생성하고, 콘텐츠 관측 행의 관계 속성으로 연결한다. 제목으로 연결하지 않는다. 확정된 키로 관측을 조회해 없으면 생성하고 한 건이면 지정 속성만 갱신한다. 여러 건이면 충돌을 보고한다. 실패한 수집으로 기존 정상값을 지우지 않는다. 유지한 값은 이전 수집 시각을 보존해 새 관측값으로 오인되지 않게 한다. 콘텐츠 DB의 최신 지표 묶음은 명세의 완전한 동일 시점·누적 범위 조건을 충족할 때만 갱신한다.
7. 저장 후 Notion을 다시 읽어 결과를 대조한다. 요청이 시간 초과되면 먼저 재조회하고 저장 여부가 불확실할 때 생성 요청을 반복하지 않는다.
8. 인사이트 권한 부족이나 인증 만료는 원인을 보고한다. 일시 오류만 정해진 한도 안에서 재시도하고, 독립적인 콘텐츠 오류는 부분 실패로 남긴다.
9. 완료 보고서를 남긴다. 예약 실행은 사용자가 운영 일정·범위를 확정했고 실제 도구가 지원하는 경우에만 설정한다. 제안값만으로 예약을 활성화하지 않으며, 설정한 예약을 확인하기 전에는 활성화됐다고 보고하지 않는다.

## 완료 보고 형식

```text
실행 ID:
상태: 성공 / 부분 성공 / 실패 / 입력·연결 대기
대상 계정:
실제 시작·종료 시각:
관측 기준일 및 원본 집계 범위:
콘텐츠 탐색 범위와 완료 여부:
과거 통계의 원본 집계 기간 및 최초 수집 재개 위치:
수집: 계정 __건, 콘텐츠 __건
Notion 저장 확인: 생성 __건, 갱신 __건
수집 실패 / 저장 확인 실패 / 중복 충돌: 각 __건
누락 지표와 사유:
재실행 대상:
추가로 필요한 입력·재인증·매핑:
```

보고서는 작업 결과를 반환하는 형태로 제공한다. 별도의 이메일·메신저 알림 채널은 사용자가 지정할 때 추가한다.
