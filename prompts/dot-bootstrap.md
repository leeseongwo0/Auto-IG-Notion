# Dot 최초 구성 지침

사용자는 Instagram 성과 공간을 새로 구성하는 작업을 위임했다. 로컬 설정의 상위 페이지 아래에 `Instagram 성과` 대시보드와 명세의 세 DB를 생성하고 첫 수집을 검증한다. 기존 캘린더의 내용을 조사하거나 이관할 필요는 없다.

## 입력과 권한 확인

- 실행 대상은 함께 제공된 로컬 설정이다. 상위 페이지 URL과 생성된 대시보드 URL을 구분한다. `null`인 결과 URL을 이미 존재하는 DB로 간주하지 않는다.
- 실제 도구로 Notion 계정·상위 페이지를 확인하고 하위 페이지·DB 생성 권한을 확인한다. 연결 도구가 제공되면 사용하고, 로그인된 브라우저가 제공되면 해당 화면을 사용한다.
- Instagram 인증이 아직 준비되지 않아도 Notion 구조 생성은 진행할 수 있다. 없는 연결 도구나 로그인 권한을 있다고 가정하지 않는다.
- 지표는 Business Suite를 우선 조회한다. 그곳에서 필요한 Instagram 인사이트를 볼 수 있으면 별도 Instagram 로그인을 필수 조건으로 요구하지 않는다.
- 명세는 도구 중립적인 구성 설명이다. JSON을 Notion API 요청으로 그대로 전송하지 말고, 사용 가능한 도구의 실제 형식과 지원 범위를 확인한다.

## 생성 및 재실행

1. 저장된 `dashboard_page_url`이 있으면 그 페이지의 상위 위치, 대상 계정, 표식 `Auto-IG-Notion · schema v1`을 확인한다. 없으면 지정된 상위 페이지의 자식 중 이름 `Instagram 성과`, 대상 계정, 표식이 모두 일치하는 페이지를 찾는다. 한 개면 재사용한다. 같은 이름의 불완전한 페이지가 있으면 이전 생성의 실행 기록과 대조해 복구하고, 출처를 확인할 수 없으면 모호함을 보고한다. 일치하는 페이지나 미해결 후보가 전혀 없을 때만 새 자식 페이지를 생성한다. 지원되면 생성 요청에 표식과 대상 계정을 함께 넣고, 아니면 생성 직후 본문에 남긴다. 다른 계정의 페이지나 이름만 같은 페이지는 덮어쓰지 않는다. 일치하는 페이지가 여러 개면 충돌로 보고한다.
2. 페이지 생성 결과를 확인하는 즉시 URL을 로컬 설정에 저장한다. 파일 접근이 없으면 실행 결과에 URL을 남기고 이후 같은 실행에서 사용한다. 요청 결과가 불명확하면 먼저 재조회하며 생성 요청을 반복하지 않는다.
3. 명세의 `content`, `content_metrics`, `account_metrics` 순서로 DB를 구성한다. 저장된 DB URL을 우선 확인하고, 없으면 대시보드 안의 해당 이름·설명·속성을 확인한다. 같은 이름의 부분 생성 후보가 있으면 이전 실행 기록으로 식별해 복구하며 출처가 불명확하면 보고하고 추가 생성을 멈춘다. 이름만 같은 DB를 임의로 재사용하지 않는다. 이전 실행이 만든 DB에 누락된 속성은 추가하되, 기존 유형 충돌은 보고한다. 속성을 삭제하거나 유형을 강제로 바꾸지 않는다.
4. 각 DB에는 명세의 이름·유형·선택 옵션을 적용한다. 콘텐츠 지표의 관계 속성은 실제로 생성한 콘텐츠 DB를 가리키도록 설정하고 대상이 정확한지 읽어 확인한다.
5. 각 DB 생성 직후 실제 URL을 로컬 설정의 대응 필드에 저장하거나 결과에 남긴다. 페이지 URL을 DB URL로 복사하지 않는다. API 도구가 별도의 데이터 소스 ID를 반환하면 후속 작업에 필요한 ID도 비공개 실행 기록으로 보존한다.
6. 명세의 보기와 정렬·필터를 적용한다. Notion API 도구가 보기 생성을 지원하지 않고 브라우저도 없다면 DB 생성 결과는 유지하고 미완료 보기만 구체적으로 보고한다. 보기 설정이 미완료이면 대시보드가 모두 완성됐다고 보고하지 않는다.
7. 실제 계정 인사이트에 접근할 수 있으면 계정 관측 한 건과 콘텐츠 한 건의 관측을 `docs/workflow.md`에 따라 기록한다. 접근할 수 없으면 가짜 예시 지표를 넣지 않고 DB를 비워 둔다.
8. 저장 결과를 다시 읽고 같은 수집 입력을 재처리해 중복 관측 행이 생기지 않는지 확인한다. 최초 구성을 다시 확인했을 때 페이지·DB가 중복되지 않는지도 점검한다.
9. 첫 저장 검증을 통과하면 `docs/initial-import.md`에 따라 기존 지표를 최초 수집한다. 기존 Notion 기록은 이관하지 않는다. 최근 30일 콘텐츠를 먼저 처리하고 접근 가능한 과거 콘텐츠·기간 통계까지 이어가며, 진행 위치를 비공개 기록으로 남긴다.
10. 이후 정기 수집 제안은 최근 30일 게시물·릴스, 매일 09:00 Asia/Seoul이며 아직 사용자 확정 일정은 아니다. 초기 구성과 최초 수집은 계속 진행하고, 운영 일정과 정기 범위가 확정되기 전에는 예약을 활성화하지 않는다. 사용자가 확정한 일정이 있고 실제 예약 도구를 사용할 수 있으며 첫 수집 검증이 끝난 경우 반복 실행 지침으로 예약을 설정한다. 기존 동일 예약이 있으면 재사용한다. 초기 수집이 진행 중이면 정기 실행과 동시 쓰기가 일어나지 않도록 직렬화한다. 예약 결과와 다음 실행 시각을 확인한 경우에만 활성화로 보고한다.

## 생성 결과

다음 항목을 실제 확인한 값으로 반환한다.

- 대시보드 URL과 세 DB URL.
- 재사용·생성·부분 구성한 항목 및 속성·관계·보기 검증 결과.
- 첫 수집과 저장 재확인 결과; 실행하지 못한 경우 정확한 이유.
- 기존 지표의 조회 가능 범위, 실제 최초 수집 범위, 미완료 범위와 재개 위치.
- 중복 방지 검증 결과.
- 예약 상태: 미설정 / 설정했으나 확인 필요 / 활성화 확인, 다음 실행 시각.
- 남은 입력·권한·지원 기능.

연결이나 권한이 없으면 해당 작업의 중단 사유를 명확히 보고한다. 텍스트 초안 작성이나 생성 요청 전송만으로 실제 생성 완료를 보고하지 않는다. 비밀번호·토큰·쿠키는 보고서나 로컬 설정에 넣지 않는다.
