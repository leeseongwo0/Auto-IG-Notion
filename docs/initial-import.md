# 기존 지표 최초 수집

기존 Notion 자료 이관은 범위에서 제외합니다. Meta Business Suite에서 실제로 접근 가능한 기존 Instagram 지표를 새 성과 DB에 수집하고, 이후 정기 수집으로 연결합니다. 이 문서는 실행 지침이며 실제 수집 완료를 뜻하지 않습니다.

## 가져올 범위

| 자료 | 저장 방법 |
| --- | --- |
| 기존 게시물·릴스 | 콘텐츠 기본 행에 원래 게시일·고유 링크·종류 저장 |
| 과거 콘텐츠의 현재 누적 성과 | 콘텐츠 지표에 실제 수집일·수집 시각 기준 관측으로 저장 |
| 과거 기간의 조회·도달 | 계정 지표에 원본 집계 시작·종료·시간대와 실제 수집 시각을 함께 저장 |
| 현재 팔로워 수 | 현재 시점의 계정 관측에 저장. 과거 기간 행에 복제하지 않음 |

콘텐츠는 최근 30일을 먼저 처리한 다음 접근 가능한 이전 게시물·릴스까지 이어서 수집합니다. 계정 통계의 조회 가능 기간은 현장에서 확인해 기록하며 특정 기간의 보관을 미리 보장하지 않습니다. 스토리, 메시지, 연락처, 광고비, 기존 Notion 기록은 이번 수집 대상이 아닙니다.

과거 날짜의 팔로워 원본 값이 제공되는 경우 그 날짜와 지표 정의를 원본 보고서에 보존합니다. 현재 스키마의 팔로워 속성은 수집 시점 값이므로 과거값으로 덮어쓰지 않습니다. 과거 팔로워 시계열까지 확장할 때는 기준일 속성과 매핑을 별도로 정의합니다.

## 출처와 날짜 규칙

- Business Suite를 우선 사용합니다. 필요한 지표가 없을 때만 접근 가능한 Instagram 인사이트로 보완합니다. 지표의 원본 이름·기간·유기적/광고 포함 범위를 `원본 지표명`과 비고에 남깁니다.
- 조회와 재생, 유기적 성과와 광고 포함 성과처럼 정의가 다른 값을 같은 지표로 합치거나 덮어쓰지 않습니다. 같은 정의인지 확인할 수 없으면 별도 원본으로 보존하고 해당 속성 쓰기는 보류합니다.
- 원본이 공식 내보내기를 제공하면 파일을 사용할 수 있습니다. 원본 파일은 Git에서 제외한 `data/`에 보관하고, 표시되는 날짜의 의미와 집계 범위를 확인한 뒤 매핑합니다.
- `게시일`은 게시된 날짜, `관측일`은 실제 수집일, `집계 시작·종료`는 통계가 설명하는 기간입니다. 오늘 읽은 누적값을 콘텐츠 게시일의 수치로 기록하지 않습니다.
- 과거 기간 보고서는 집계 기간을 기준으로 해석합니다. 관측일로 정렬한 화면은 수집 이력이며 과거 성과의 날짜 축이 아닙니다.
- 동일한 과거 기간을 여러 날에 걸쳐 다시 조회하면 각각의 관측을 보존합니다. 기간 비교에는 같은 정의·기간의 최신 검증 관측 하나만 선택하고 중복 합산하지 않습니다.
- 월간 도달을 일별로 분배하거나 일별 도달을 합산해 월간 고유 도달을 만들지 않습니다. 원본이 일별 자료를 제공할 때만 일별 기록을 가져옵니다.

## 실행 순서

1. 대상 계정과 연결을 확인하고 계정 통계의 조회 가능 기간, 콘텐츠 목록의 탐색 범위, 내보내기 가능 여부를 기록합니다.
2. 최초 구성 지침으로 새 DB를 만들고 계정 한 건·콘텐츠 한 건의 수집 및 저장 재확인을 통과합니다.
3. 최근 30일 콘텐츠부터 시작해 이전 콘텐츠로 진행합니다. 목록이 끊기거나 더 불러올 수 없으면 원인과 실제 도달 범위를 기록합니다. 고정 게시물만 보고 탐색을 종료하지 않습니다.
4. 계정의 현재값과 제공되는 과거 기간 통계를 각각 수집합니다. 계정 지표에서 서로 다른 기간의 조회·도달은 별도 관측으로 나눕니다.
5. 수집값을 검증한 뒤 정해진 기록 키로 Notion을 조회·갱신하고 저장 결과를 다시 읽습니다. 같은 입력을 재처리해 중복을 확인합니다.
6. 25개 콘텐츠 단위로 진행 상태를 저장합니다. 더 작은 묶음이 필요한 경우 줄일 수 있습니다. 인증 만료나 일시 실패 후에는 확인된 작업부터 이어갑니다.
7. 접근 가능한 범위와 실제 완료 범위를 대조해 초기 수집 결과를 보고합니다. 이후 정기 수집은 최근 30일 콘텐츠와 현재 계정 통계를 기본 대상으로 합니다. 오래된 콘텐츠의 매일 갱신은 이 기본 범위에 포함되지 않습니다.

## 중단 후 이어가기

`runtime/initial-import-progress.json` 또는 Dot의 비공개 작업 기록에 다음을 남깁니다. 영속 기록 기능이 없으면 이 정보를 사용자에게 반환하고 예약 작업이 기억한다고 가정하지 않습니다.

- 실행 ID와 대상 계정, 원본 조회 기간·시간대·지표 정의.
- 목록의 다음 탐색 위치와 처리한 콘텐츠 ID; 위치가 만료되면 목록을 다시 읽어 ID로 확인.
- 수집한 원본 자료 위치와 실제 관측 시각.
- Notion에서 저장을 확인한 키·페이지, 확인되지 않은 요청과 실패 항목.
- 마지막 완료 시각 및 남은 범위.

이미 보관한 수집 자료를 다시 쓰는 경우 원래 관측일·시각을 유지합니다. 원본 서비스를 다시 조회한 경우에만 새 관측일·시각을 부여합니다. 생성 요청 결과가 불명확하면 키로 재조회한 후 복구합니다.

## 완료 보고

탐색 가능한 범위, 실제 수집 범위, 완료·부분 수집·실패 건수, 원본의 기간 제한, 확보하지 못한 지표, 남은 작업과 다음 실행 위치를 보고합니다. 최근 30일만 처리했으면 전체 초기 수집 완료로 표시하지 않습니다. 과거 일별 원본이 없는 지표는 복원할 수 없는 항목으로 명시합니다.
