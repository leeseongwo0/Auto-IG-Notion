# Instagram 성과: 새 Notion 구성

사용자가 지정한 부모 페이지 아래에 **Instagram 성과** 페이지와 새 데이터베이스 세 개를 만듭니다. 실제 주소와 계정은 Git에서 제외한 `config/local.json`에서 읽습니다.

이 문서는 생성할 구성을 확정한 설계입니다. 현재 이 대화에는 Notion 도구가 없어 페이지와 데이터베이스를 실제로 만들지 않았습니다. [속성 명세](../notion/schema.json)는 Dot이 연결 도구나 브라우저로 구현할 도구 중립 형식이며, Notion API 요청 본문이 아닙니다.

## 페이지 구성

```text
사용자가 지정한 부모 페이지
└─ Instagram 성과
   ├─ 수집 안내: 대상 계정, 시간대, 최근 실행 결과
   ├─ 콘텐츠 캘린더 — 게시일 기준
   ├─ 최신 콘텐츠 성과 — 콘텐츠별 검증된 최신 누적값
   ├─ 콘텐츠 성과 이력 — 관측일 기준
   ├─ 계정 추이 — 관측일 내림차순
   ├─ 확인 필요 — 부분 수집·검증 실패
   └─ 원본 DB: 콘텐츠 / 콘텐츠 지표 / 계정 지표
```

페이지에 `Auto-IG-Notion · schema v1`과 대상 계정 식별자를 기록합니다. DB는 같은 페이지 아래에 만들고 각 DB 설명에 동일한 표시와 DB 키를 남깁니다. 재실행할 때 우리가 만든 구조를 식별하기 위한 표시입니다.

## 데이터베이스와 행의 의미

| 데이터베이스 | 한 행의 의미 | 핵심 속성 |
| --- | --- | --- |
| 콘텐츠 | 게시물 또는 릴스 하나 | 콘텐츠명, 콘텐츠 키, 계정 식별자, 콘텐츠 식별자, 원본 링크, 종류, 게시일, 최신 누적 지표 |
| 콘텐츠 지표 | 콘텐츠 하나의 날짜·집계 범위별 관측 | 기록 키, 콘텐츠 관계, 관측일, 수집 시각, 집계 범위·기간, 조회·도달·좋아요·댓글·저장·공유 |
| 계정 지표 | 계정 하나의 날짜·집계 범위별 관측 | 기록 키, 계정, 관측일, 수집 시각, 팔로워, 조회·도달, 조회·도달 집계 범위·기간 |

콘텐츠 지표의 `콘텐츠` 관계는 콘텐츠 DB의 한 행을 가리킵니다. 계정 지표에는 콘텐츠 관계를 만들지 않습니다. 모든 수치 속성은 숫자이며 누락은 빈값입니다. 제목이나 날짜만으로 같은 콘텐츠라고 판정하지 않습니다.

정확한 속성 이름·유형·선택 옵션·보기 설정은 `notion/schema.json`이 기준입니다. 기본 제목·텍스트·숫자·날짜·URL·선택·관계 속성만 사용하며 수식이나 차트 지원을 전제로 하지 않습니다.

기록 키는 명세의 `key_components` 순서대로 실제 값을 넣은 JSON 배열을 문자열로 직렬화합니다. 기간 경계가 없으면 JSON `null`을 쓰며, 기간을 확인할 수 없을 때는 원본 기간 문구를 포함한 일관된 미확인 범위 표기를 사용합니다. 구분자로 문자열을 임의 연결하지 않습니다.

## 최신값과 관측 이력

- **콘텐츠 지표**에 관측 이력을 먼저 저장하고 다시 읽습니다. 같은 콘텐츠·관측일·집계 범위·기간 경계이면 같은 `기록 키`로 갱신합니다.
- **콘텐츠**의 `최신 조회` 등 여섯 숫자는 검증된 **누적 관측 한 건의 묶음**만 복사합니다. 적용 가능한 지표를 모두 확인해야 하며, 원본에서 미제공임을 확인한 지표는 빈값과 사유로 복사할 수 있습니다.
- 읽기 실패, 축약값만 확인, 기간 불명확, 저장 미확인이 남으면 최신 묶음을 교체하지 않습니다. 부분 관측을 이력에 남기고 `최근 수집 상태`·`최근 시도 시각`·`최근 수집 비고`를 갱신합니다.
- 현재 최신 관측보다 오래된 관측을 재처리해도 최신값을 뒤로 돌리지 않습니다. `최신 수집 시각`·`최신 기록 키`·`최신 지표 비고`는 복사된 묶음에 속하며, 최근 수집 시도 정보와 구분합니다.
- 묶음 갱신 전에 `최신 지표 상태`를 `검증 중`으로 바꾸고, 숫자·메타데이터 갱신 후 다시 읽어 일치하면 `검증 완료`로 바꿉니다. 최신 성과 보기는 검증 완료만 표시해 중간 실패한 혼합값을 정상 최신값으로 노출하지 않습니다.
- 기간별 지표처럼 누적과 다른 범위는 관측 이력에 보관합니다. 단순 합계나 최댓값 롤업을 최신값으로 쓰지 않습니다.

계정의 `팔로워`는 `팔로워 수집 시각`의 순간값입니다. 조회·도달에는 `집계 범위`·`집계 시작`·`집계 종료`·`원본 기간 표기`가 적용됩니다. 최근 30일 도달을 일별 도달로 해석하거나 합산하지 않습니다. 조회와 도달의 기간이 다르면 별도 관측으로 나눕니다.

## 기본 보기

| 보기 | 원본 DB | 규칙 |
| --- | --- | --- |
| 콘텐츠 캘린더 | 콘텐츠 | 게시일 기준 달력; 종류·원본 링크 표시 |
| 최신 콘텐츠 성과 | 콘텐츠 | 최신 지표 상태가 검증 완료인 행, 게시일 내림차순; 수치·최신 수집 시각·최근 수집 상태 표시 |
| 전체 콘텐츠 | 콘텐츠 | 게시일 내림차순; 최신 지표가 없는 콘텐츠 포함 |
| 콘텐츠 성과 이력 | 콘텐츠 지표 | 관측일·수집 시각 내림차순 |
| 오늘 수집 | 콘텐츠 지표 | Asia/Seoul 기준 오늘 관측 |
| 계정 추이 | 계정 지표 | 관측일·수집 시각 내림차순; 집계 범위와 팔로워 시각 포함 |
| 확인 필요 | 각 DB | 부분 수집·확인 필요인 행; 콘텐츠는 검증 중인 최신값도 포함 |

도구가 연결된 보기를 만들 수 없으면 원본 DB 안의 동일한 보기를 만들고 대시보드에 원본 링크를 둡니다. 실제 확인한 생성 결과만 보고합니다. 상대 날짜 필터는 Asia/Seoul을 기준으로 적용합니다.

## 생성·재실행 순서

1. 로컬 설정의 부모 페이지와 대상 계정을 확인합니다. 저장된 대시보드·DB 주소가 있으면 그 객체의 표시와 속성을 먼저 확인합니다.
2. 저장 주소가 없으면 지정 부모 페이지의 직접 하위에서 제목·표시·대상 계정이 일치하는 대시보드를 찾습니다. 한 개면 재사용하고 여러 개면 충돌을 보고합니다. 제목만 같은 페이지를 재사용하지 않습니다.
3. 일치하는 대시보드가 없을 때 생성하고 반환된 주소를 저장 또는 보고합니다. 생성 응답이나 표시·주소 저장이 불확실하면 재조회합니다. 같은 이름이지만 표시가 없는 객체는 부분 생성일 수 있으므로 이번 실행 또는 프로젝트의 객체임을 확인할 수 있을 때만 복구하고, 불확실하면 추가 생성 없이 충돌을 보고합니다.
4. 대시보드 안에서 `content` → `content_metrics` → `account_metrics` 순서로 DB를 확인·생성합니다. DB에도 위의 부분 생성 복구 규칙을 적용합니다. 주소나 표시가 맞는 DB는 재사용하고, 누락 속성만 추가합니다. 기존 속성 유형을 임의로 바꾸지 않습니다.
5. 콘텐츠 지표의 관계가 실제 콘텐츠 DB를 가리키는지 확인하고 보기를 만듭니다. 생성된 주소는 로컬 설정에 저장하거나 반환합니다. 부모 페이지 주소와 생성된 대시보드 주소를 구분합니다.
6. 실제 계정 관측 한 건과 콘텐츠 관측 한 건을 기록·재조회합니다. 같은 입력 재처리에서 콘텐츠·관측 행 수가 증가하지 않는지 확인합니다. 가짜 지표나 예제 행은 만들지 않습니다.
7. 전체 수집을 실행하고 결과를 보고합니다. 예약 실행은 도구의 지원 여부와 실제 등록 결과를 확인합니다.

생성과 수집은 한 번에 한 실행만 진행합니다. Notion이 키의 고유성을 강제하거나 조회·생성을 원자적으로 처리한다고 가정하지 않습니다.
